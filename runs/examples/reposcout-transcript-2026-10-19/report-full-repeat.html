Method

Variants. full: Production today: description plus the whole transcript (capped at 45,000 characters), one standard-level call with the production prompt. jev-filter: Same prompt and model; the transcript first goes through Jev in 700-character chunks, keeping chunks scored at or above 0.5 plus 1 neighbor on each side and always the first two. jev-strict: Same prompt and model; the transcript first goes through Jev in 700-character chunks, keeping chunks scored at or above 0.75 and always the first two. full-repeat: The baseline run a second time on the same inputs. Its distance from full is the noise floor: any candidate change smaller than this is not evidence.

Checks. json_valid (code): The reply parsed as the Extraction schema within two attempts linked_recall (code): Every repo linked in the description is named by the model before the merge backfills it item_recall (code): Every repo or tool production recorded for this video appears in this variant's items (matched by URL, key or name, no network) categories_valid (code): Every item category is in the allowed set no_em_dash (code): No em dash in any output text

Gate. Candidate pass-all may not drop by more than 0%, and the rate of item_recall and linked_recall may not be lower on the candidate. Regressions per case are listed, not gated.

Numbers. Token counts and cost come from the provider's usage report on every call (metered). Cost is the API-equivalent figure; these calls ran on a subscription. Latency is wall time per case including every call the variant made. Intervals: Wilson for rates, seeded percentile bootstrap (2,000 resamples) for paired means. No p-values.

Pairing. Only cases both variants completed are compared, in suite order, so every paired number has the same n (46). Errors: 0 on full, 0 on full-repeat.
